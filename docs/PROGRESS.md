## 1. Что это

Telegram Mini App «WISHLLY» — вишлист: добавляешь желания (фото, цена, ссылка), сортируешь по группам
(«День рождения», «Новый год»…), делишься ссылкой; друзья тайно бронируют подарки.

- Папка проекта: `/Users/vladislav/Desktop/wishlly`
- Git: `git init` выполнен в папке проекта (раньше git-корнем была домашняя папка). **Коммитов ещё нет.**
- Язык общения и UI: русский.

## 2. Стек и архитектура

| Слой | Технология |
|---|---|
| Frontend | Vite 8 + React 18 + TypeScript (strict: false) + Tailwind v4 (`@tailwindcss/vite`) + `tw-animate-css` + `lucide-react` |
| Данные | Firebase Firestore (клиентский SDK, realtime `onSnapshot`) |
| Авторизация | Telegram `initData` → `/api/auth` (проверка HMAC подписи ботом) → Firebase custom token, uid = `tg_<telegramId>`. Вне Telegram — анонимный вход (только для локальной разработки) |
| Backend | Express (`server/index.ts`, роуты в `server/routes/*.ts`), запуск `tsx server/index.ts`, отдаёт также `dist/` |
| Бот | Webhook `server/routes/telegramWebhook.ts`: на `/start` отвечает кнопкой `web_app` → `WEBAPP_URL` |
| Хостинг | VPS: nginx → Express (`:3001`), systemd user-сервис `wishlly`, автодеплой из GitHub Actions (`.github/workflows/deploy.yml`) по push в `main`. Домен `wishlly.ru`. Конфиги — `deploy/` |

### Модель данных Firestore

Путь: `artifacts/{VITE_APP_ID}/public/data/...`

- `wishes/{id}`: `title, price, link, imageUrl (base64 JPEG ≤600px), groupId ('unassigned' | id группы), ownerId, ownerName, reservedBy (uid | null), createdAt`
- `groups/{id}`: `name, ownerId, createdAt`
- `profiles/{uid}`: `birthdate, gender ('Мужской'|'Женский'), onboardingCompleted, createdAt`

### Ключевые решения (не менять без причины)

- Ссылка «Поделиться»: `https://t.me/<VITE_BOT_USERNAME>/app?startapp=<uid>` или `<uid>-<groupId>`.
  Разделитель `-`, т.к. uid `tg_123` содержит `_`. Разбор — `parseStartParam()` в `App.tsx`.
- Режим гостя: если `start_param.ownerId !== user.uid` → показываем вишлист владельца, баннер «Вишлист друга»,
  кнопка «Мой вишлист». Кнопки «+» и «Профиль» выходят из режима гостя.
- В Telegram при ошибке `/api/auth` — экран «Не удалось войти» + «Повторить» (без фолбэка на анонимный вход).
- Ссылки на товар рендерятся только если `http(s)://` (`isSafeLink`) — защита от `javascript:` XSS.
- Подписки Firestore — только `where('ownerId', '==', viewedOwnerId)`; счётчик «Я дарю» — отдельный запрос `where('reservedBy','==',uid)`.

### Найдено и исправлено при первом ручном тесте (п.6)

- 🔴 Экран «Не удалось войти» при каждом открытии Mini App. Диагностика: `/api/auth` и `verifyInitData` работали
  корректно (проверено сквозным тестом с подписанным initData — сервер отдавал валидный custom token), но
  `signInWithCustomToken` на клиенте падал. Обмен custom token → id token напрямую через Identity Toolkit REST API
  показал `400 CONFIGURATION_NOT_FOUND` — **в Firebase-проекте `wishlly-932c0` ни разу не был активирован раздел
  Authentication** (Firestore и Authentication включаются в консоли независимо друг от друга).
  ✅ **Пользователь** зашёл в Firebase Console → Authentication → Get started → активировал.
  Перепроверено тем же REST-обменом: `signInWithCustomToken` → `200 OK`, `idToken` получен. Проблема решена.
  Диагностическое логирование, добавленное на время поиска причины, убрано из `api/auth.ts` после подтверждения фикса.

### Найдено и исправлено: желания не сохранялись («крутится сохранение»)

- 🔴 После входа добавление желания зависало на сохранении. Диагностика (сквозной REST-тест: подписанный initData →
  custom token → idToken → прямая запись в Firestore) показала `403 PERMISSION_DENIED` даже на простое чтение
  коллекции `wishes` при валидном `signedIn()` пользователе — значит, в консоли Firebase всё ещё действовали
  правила по умолчанию (запрет всего), а не содержимое `firestore.rules` из репозитория (публикация из п.3a не
  применилась/не была фактически сохранена).
  ✅ **Пользователь** заново вставил и опубликовал `firestore.rules` в Firebase Console → Firestore → Rules.
  Перепроверено тем же REST-тестом: запись `200 OK`. Тестовый документ удалён через Admin SDK.

### Найдено и исправлено: длинный текст желания вылезал за пределы карточки

- 🟡 `line-clamp-2` на заголовке желания не переносил длинные слова без пробелов (например, вставленную ссылку) —
  `flex-grow`-контейнер без `min-w-0` не сжимался, текст вылезал за карточку.
  ✅ Добавлен `min-w-0` на контейнер деталей и `break-words` на заголовок (`src/App.tsx`).
- 🟡 Заодно: поле ввода названия желания не имело ограничения длины, а `firestore.rules` отклоняет `title` длиннее
  200 символов — при превышении сохранение молча зависало бы (тот же симптом, что был с rules). Добавлен
  `maxLength={200}` на input.
  `tsc`/`build` зелёные, задеплоено на прод.
- 🟡 Поле «Цена» — тоже свободный текст (не только число), бейдж под него был `inline-block` без ограничения
  ширины/переноса → тоже вылезал за карточку при длинном значении. Добавлены `max-w-full` на бейдж и
  `break-words line-clamp-1` на текст цены.
